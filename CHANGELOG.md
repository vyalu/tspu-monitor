# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
Каждая версия отсюда автоматически публикуется как [релиз на GitHub](https://github.com/vyalu/tspu-monitor/releases).

## [1.5.1] — 2026-11-12

### Изменено
- Под цепочкой шагов объясняется, почему серые шаги не проверены: соединение не проходит дальше шага, где стоит блокировка.

## [1.5.0] — 2026-11-12

### Добавлено
- Статус «сильное замедление»: если TLS оборвался по таймауту, рукопожатие повторяется с ожиданием до 20 секунд. Прошло — значит, сайт не заблокирован, а замедлен (как YouTube). Тревога поднимается, как и при блокировке.

### Изменено
- Разбор блокировок показан цепочкой шагов в постоянном порядке: DNS → IP-адрес → Имя (SNI) → Загрузка → Ответ сайта, отдельно HTTP/3 и белые списки. У каждого шага отметка: не блокируется, блокировка, не удалось проверить или проверка не дошла. Под цепочкой — понятное пояснение к каждой блокировке, технический текст ошибки свёрнут в «Технические подробности».

### Исправлено
- При обрыве TLS монитор мог написать «блокировки не найдены — похоже на сбой у самого сервера», если не с чем было сверить имя сайта (контрольные сайты ещё не проверены или выключены). Теперь место, где сломалась основная проверка, всегда отмечается как блокировка, а для сверки имени есть запасные серверы.

## [1.4.0] — 2026-11-12

### Добавлено
- «Блокировки сейчас»: при сбое монитор проверяет каждый уровень отдельно и показывает все действующие блокировки сразу — DNS, по IP, по SNI, HTTP/3 (QUIC), обрыв загрузки, заглушка, белые списки. Рядом — что не блокируется и что проверить не удалось.
- Проверка SNI отдельно от адреса: имя сайта отправляется на посторонний доступный сервер и сравнивается со случайным безобидным именем.
- Список блокировок — на карточке, в окне тревоги, в уведомлении браузера и в журнале событий; если набор блокировок меняется во время сбоя, это тоже попадает в журнал.

## [1.3.0] — 2026-11-12

### Добавлено
- Статус «заглушка о блокировке вместо сайта»: провайдер перенаправил на страницу блокировки или отдал текст о блокировке по решению РКН. Раньше такая заглушка по `http://` могла считаться рабочим сайтом.
- Предупреждения — сайт открывается, но в браузере могут быть проблемы. Тревогу не поднимают, пишутся в журнал событий, отключаются в настройках:
  - **замедление** — скорость загрузки ниже порога (по умолчанию 300 кбит/с);
  - **HTTP/3 (QUIC) не проходит** — для сайтов, которые объявляют HTTP/3; монитор отправляет настоящий первый пакет QUIC с именем сайта и ждёт ответа, не чаще раза в 10 минут;
  - **сайт публикует ECH** — подключения с шифрованным именем в России режут, браузер может не открыть сайт;
  - **ответ не похож на обычный** — другой заголовок страницы и в разы меньший объём, чем в прошлых проверках.
- На карточке ресурса — скорость загрузки и состояние HTTP/3.
- Раздел «Дополнительные проверки» в настройках.

### Изменено
- По-прежнему без внешних зависимостей: шифрование пакета QUIC (AES-128-GCM) реализовано в `app/quic.py` и сверено с тестовыми векторами RFC 9001.

## [1.2.0] — 2026-11-12

### Исправлено
- Сайт, который перенаправляет на другой адрес (например, `example.ru` → `www.example.ru`), раньше считался рабочим по первому ответу, даже если конечный адрес заблокирован. Теперь монитор, как браузер, проходит по перенаправлениям (до 5) и проверяет каждый адрес полностью: DNS, TCP, TLS, загрузку.

### Добавлено
- Статус «сервер отказал в доступе (HTTP 403/451)» — сайт сам не пускает: геоблокировка для российских IP или защита от ботов.
- Статус «сервер ответил ошибкой HTTP» — 404, 5xx или зациклившиеся перенаправления.
- Номер версии в шапке страницы и в журнале контейнера.
- Автоматические релизы на GitHub: при смене номера в `app/VERSION` публикуется релиз с описанием из этого файла.

### Изменено
- Запрос к сайтам идёт с заголовками обычного браузера. Контрольные сайты по-прежнему оцениваются только по сетевой доступности, без учёта кода ответа.

## [1.1.0] — 2026-11-09

### Добавлено
- Новое оформление README: баннер, скриншоты, описание возможностей.
- Демо-стенд с выдуманными данными и скрипты для картинок (`tests/demo/`).

### Исправлено
- Фраза в окне тревоги: «Подан звуковой сигнал» вместо «Отправлено звуковой сигнал».

## [1.0.0] — 2026-11-09

Первая публичная версия.

- Проверка по шагам: DNS → TCP → TLS → загрузка; статусы блокировки по SNI, по IP / белому списку, TCP 16-20, подмены DNS и сертификата.
- Вердикт по контрольным сайтам: режим белых списков, отсутствие интернета.
- Тревога в браузере: окно поверх страницы, звук, уведомление, мигающая вкладка.
- История за сутки и неделю, выгрузка CSV, диагностика при сбое (Globalping, сверка DNS, трассировка).
- Вход администратора, просмотр без входа, Docker с ограниченными привилегиями.
